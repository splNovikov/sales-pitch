1. ПРЕДЛОЖЕНИЕ
   1.1. Архитектура решения
   Предлагаемое архитектурное решение системы обнаружения аномалий в данных телеметрии нефтегазодобывающих установок представляет собой разработку, интеграцию и эксплуатацию трёх ключевых компонентов.

Первый компонент — это Data Lake, который обеспечивает распределенное хранение и обработку больших объемов исторических данных, полученных от датчиков оборудования, систем ДНС и иных периферийных узлов. Помимо телеметрических сигналов, Data Lake организует совместное хранение информации об инцидентных событиях в функционировании оборудования и результатах разметки аномальных участков данных.
Процесс наполнения Data Lake выполняется посредством ETL-процессов, которые осуществляют загрузку исторических данных устройств из промежуточной базы данных и информационной системы 1С, содержащей сведения об инцидентах и изменениях настроек оборудования. Для достижения высокого быстродействия и своевременного реагирования Data Lake используется также для потоковой выгрузки данных из вышеуказанных источников через ETL-процессы.
В качестве технологической основы для реализации Data Lake рассматриваются следующие свободно распространяемые системы:
HDFS (Hadoop Distributed File System) — распределенное хранилище данных.
Apache Kafka — система потоковой передачи данных с гарантированной доставкой.
Apache Spark и Apache Spark Streaming — системы распределенной обработки данных, включая потоковую аналитику.
Apache Airflow — система управления ETL-процессами и планировщик задач.

Второй компонент — это подсистема поиска аномалий в собираемых данных. Основная задача этого компонента — выявление отклонений в работе оборудования, которые могут сигнализировать о приближающемся аварийном состоянии, выходе из строя или иных видах инцидента. Такой алгоритм должен определять аномалии заблаговременно  до наступления аварии, выполняя раннюю диагностику и классификацию текущих состояний оборудования. Данный компонент функционирует поверх Data Lake и реализует набор специально разработанных  аналитических и предиктивных алгоритмов, исполняющихся и управляемых с помощью ETL-процессов на платформе Apache Spark с соответствующими расширениями в виде библиотек.

Третий компонент — это графический интерфейс оператора системы, обеспечивающий наглядное представление поведения оборудования с выделением участков аномального функционирования, классифицированных аномалий, возможностью фильтрации, поиска и масштабирования данных. Интерфейс осуществляет информирование оператора и других уполномоченных сотрудников о выявленных предпосылках к возникновению ненормативных ситуаций. Кроме того, предусмотрена многоуровневая система доступа, основанная на механизмах разграничения полномочий пользователей и ролей, что позволяет ограничить круг лиц, имеющих право доступа к оборудованию определенной группы. Также в состав интерфейса входит модуль для верификации, разметки аномалий и их последующей корреляции с зафиксированными инцидентами.Интерфейс реализуется с применением следующих свободных технологий:
PostgreSQL — реляционная СУБД для хранения данных.
Node.js — технология для реализации серверной части системы.
React — библиотека JavaScript для построения UI-компонентов пользовательского интерфейса.

Все компоненты системы планируется развернуть в контур безопасности организации с использованием открытого оркестратора контейнеров Kubernetes, обеспечивающего автоматизацию развертывания, масштабирования и управления приложениями, упакованными в Docker-контейнеры. Kubernetes обеспечивает надежную работу приложений как в облачных, так и в локальных физических инфраструктурах.
Дополнительно необходима  интеграция CI/CD платформы (GitLab + Hashicorp Terraform + ) для поддержания системы контроля версий исходных кодов, автоматизированной сборки, интеграции и развертывания компонентов системы.
