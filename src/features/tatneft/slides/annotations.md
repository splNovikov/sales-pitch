## 8. Общая схема взаимодействия компонентов

**Аннотации (что донести):**

- Сразу внедрить термин Data Lake (слой хранения данных).
- Внедрить терминологию: что такое аномалия.
- Внедрить терминологию: что такое SCADA, сколько типов SCADA бывает.
- Донести: для любой системы необходимо хранение данных.
- Донести: наша задача — in advance предупреждать операторов.

**SCADA** — Supervisory Control and Data Acquisition (диспетчерское управление и сбор данных).

**SCADA (коротко):** система диспетчерского контроля и сбора данных с объектов (датчики, оборудование).

**SCADA (развёрнуто):** программно-аппаратный комплекс для сбора телеметрии с датчиков и оборудования в реальном времени, визуализации состояния процессов и диспетчерского управления. В нефтедобыче — источник данных с ДНС, скважин, ГЗУ и др. В контексте КП — один из типов систем-источников, из которых данные попадают в Data Lake через ETL.

**Текст спикера:**

На схеме — три компонента. Слой хранения данных мы называем Data Lake: без единого хранилища телеметрии невозможна работа алгоритмов раннего предупреждения. Поверх — подсистема предупреждений, которая анализирует данные и формирует оповещения. Третий блок — интерфейс оператора. Наша задача — предупреждать операторов заранее, до инцидента. Кратко: Data Lake — единое хранилище; SCADA и другие системы — источники данных; подсистема предупреждений и интерфейс завершают цепочку.

## 18. Data Lake: схема

**Data Lake (коротко):** единое хранилище телеметрии и инцидентов.

**В нашем случае Data Lake — это:** единое хранилище телеметрии с датчиков оборудования и информации об инцидентах. Данные выгружаются (ETL из источников), очищаются и приводятся к единому формату. Фундамент для подсистемы раннего предупреждения и интерфейса оператора. В скоупе текущего КП — данные по ДНС.

**ETL** — Extract, Transform, Load (извлечение, преобразование, загрузка).

**ETL (коротко):** выгрузка из источников, очистка и загрузка в хранилище.

**ETL (развёрнуто):** процесс выгрузки данных из систем-источников (SCADA, АСУТП и др.), их преобразования — очистка, приведение к единому формату и структуре — и загрузки в единое хранилище (Data Lake). Обеспечивает «один источник правды» для аналитики и подсистемы предупреждений.

**Аннотации (что донести):**

- Упомянуть: используем только импортозамещённые решения (решения должны отвечать требованиям безопасности и прочим).
- Упомянуть: список требований будет утверждён на этапе аналитики и т.д.

**Текст спикера:**

На схеме — источники данных, процесс ETL и само хранилище. Данные из SCADA и других систем извлекаются, преобразуются и загружаются в Data Lake. Мы ориентируемся на импортозамещённые решения; итоговый список требований будет утверждён на этапе аналитики.

## 22. Подсистема предупреждений

**Текст спикера:**

Подсистема предупреждений — набор алгоритмов, которые анализируют данные из хранилища, находят отклонения в поведении оборудования и формируют оповещения о рисках до наступления инцидента. Ключевая цель — заблаговременное выявление отклонений в работе оборудования до наступления аварии. На старте будет много срабатываний аномалий, по-настоящему предаварийных — немного; в ходе эксплуатации соберём информацию о действиях оператора, чтобы в перспективе формулировать рекомендации. Ценность — ранние предупреждения, снижение простоев, откалиброванная подсистема и накопление обратной связи для будущих рекомендаций.
